# User App Demo Readiness

Phase 11D turns the current User App MVP shell into an operator-led demo that
can be shown, checked, and discussed without expanding production scope.

Status marker: registry chain paused after Phase 10U. Phase 10V is not the
active next phase.

## Current Demo Entry

- Run the local app with `npm run dev`.
- Open the local Vite URL.
- The app defaults to `用户 App 预览`.
- The default path is the ordinary-user MVP shell, not Template Studio.

## Recommended Demo Path

1. Open the local page.
2. Enter User App MVP.
3. Review template selection.
4. Open a template detail page.
5. Review preparation and tool checklist.
6. Start step-by-step practice.
7. Use previous, next, and complete-step actions.
8. Finish the makeup practice.
9. Review the completion page.
10. Return to template selection or restart the same look.

## Before Demo

- Run `npm run mediapipe:check`.
- Run the Phase 11D scoped tests.
- Confirm the default page starts on `用户 App 预览`.
- Confirm mobile width still shows template cards and core actions.
- Confirm ordinary users do not see registry, write-gate, simulator, approval
  boundary, production writer, Pipeline Trace, debug JSON, published, written
  registry, production ready, or raw model confidence wording.

## User Path Demo Checklist

- Home shows the local MVP shell and privacy reminder.
- Template selection shows local demo templates.
- Template detail shows step preview and region guidance.
- Preparation shows tools, product placeholders, and the first practice focus.
- Step guide shows region, goal, tools, instruction, tips, common mistakes, and
  mobile-sized actions.
- Completion shows completed step count, completed regions, step review,
  restart, and return-to-selection actions.

## Mobile Demo Checklist

- Top navigation buttons remain touch-sized.
- Template cards stack cleanly at phone width.
- Preparation action remains visible.
- Step guide actions stay large and sticky near the bottom.
- Completion actions remain readable.

## Vision Analysis Notes

- Vision Analysis remains an operator/admin surface.
- Readiness Score is a rule-based detection usability score.
- Readiness Score is not MediaPipe model raw confidence.
- When local MediaPipe assets are ready, the real local FaceMesh path can run.
- Missing MediaPipe assets should show recovery guidance instead of a generic
  failure message.

## Template Studio Notes

- Template Studio remains an administrator workflow.
- It can show FaceMesh QA, draft generation, human review, candidate packaging,
  and registry-chain review panels.
- It must not be presented as the ordinary user path.
- It must not imply publication, registry write, production writer creation, or
  current User App Shell package replacement.

## Current Cannot-Demo Scope

- No production user app.
- No backend, account, database, payment, camera, AR, OpenAI API, external AI
  API, or model training.
- No real photo upload or real user data storage.
- No real registry write, registry mutation, publication, production writer, or
  User App Shell package replacement.
- Demo templates and product suggestions are local fixture content.
- Photo-to-template remains a semi-automatic draft chain, not fully automatic
  high-quality makeup extraction.

## Demo Risk Reminders

- Do not call the MVP production ready.
- Do not say templates are published.
- Do not say the registry has been written.
- Do not describe Readiness Score as model confidence.
- Do not collect real user photos or personal data during the demo.

## Phase 12E Photo-to-Template Demo Addendum

Phase 12E adds a separate end-to-end photo-to-template demo script and
acceptance trial. The ordinary User App MVP path remains Demo Route A, while
Vision Analysis is Demo Route B and Template Studio Operator Workflow is Demo
Route C.

The acceptance trial checks whether a founder, tester, or operator can
understand the full chain:

```text
User App MVP
+ Vision Analysis
+ Template Studio Operator Workflow
+ Draft Preview QA
+ Acceptance Trial
```

This is still not production readiness. It does not resume registry writes,
does not publish, does not replace the User App Shell package, and does not
claim fully automatic high-quality makeup extraction. Semantic candidates
remain candidate-only and human-review-required.
