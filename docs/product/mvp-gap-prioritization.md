# MVP Gap Prioritization

Phase 13B converts founder/internal feedback into structured MVP gaps. This is
not a final product roadmap and not production readiness.

## Gap Dimensions

Each gap records:

- category
- priority: `p0`, `p1`, `p2`, or `p3`
- impact
- effort
- decision
- recommendation
- source feedback ids
- whether it is an MVP demo gap or production gap

## MVP Demo Gap vs Production Gap

MVP demo gaps can be considered for immediate or next sprint work. Examples:

- User App experience clarity
- trial content quality
- makeup domain accuracy
- photo-to-template semantics
- mobile polish
- trust and privacy copy
- demo readiness

Production gaps are documented but not treated as current must-do items.
Examples:

- production readiness
- monetization readiness
- broad market validation
- production analytics
- backend or registry execution

## Prioritization Rules

- `p0`: must be fixed before another credible founder/user demo.
- `p1`: should be planned for Phase 13C.
- `p2`: needs research or more founder review before implementation.
- `p3`: defer unless it blocks the demo story.
- Production readiness gaps are deferred even when high severity.

## Boundary

This prioritization keeps:

- registry chain paused after Phase 10U
- no registry write
- no publish
- no production writer
- no backend, camera, AR, AI API, analytics, or training
- no real user photos, base64, local photo paths, or personal data
