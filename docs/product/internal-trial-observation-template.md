# Internal Trial Observation Template

Phase 9A observation is a local documented template. It is not a backend record system and not a user research database.

## What To Observe

- Whether the participant understands the home screen.
- Whether the participant can find a recommended template.
- Whether the participant can start guided practice.
- Whether the participant understands the steps.
- Whether the participant understands tools and products.
- Where the participant gets stuck.
- Whether the participant understands local-only, no-upload, no-training privacy copy.
- Whether the participant is willing to continue.
- Whether the participant thinks the template content has value.

## Note Format

Use anonymous experience notes:

```text
Participant type: light makeup user
Signal: steps_understood
Observation: understood the action, but asked where the region instruction was
Issue theme: region instruction visibility
Follow-up: make region label easier to scan
```

Do not record real name, contact information, health information, sensitive identity information, precise personal identifiers, photos, face embeddings, biometric identifiers, account data, backend ids, analytics ids, or training labels.

## Blocked Observation Examples

The observation template is blocked if it asks the operator to:

- collect a selfie, photo, or camera capture;
- collect a real name or contact channel;
- collect health, sensitive identity, or biometric information;
- upload notes to a backend;
- write real participant records into `project-state`;
- feed observation notes into training data.

## Summary Format

Use aggregate themes only:

- Positive signals.
- Confusing moments.
- Content issues.
- Shell usability issues.
- Privacy trust issues.
- Suggested next action.

The summary may use mock/example data in documentation and UI, but it must be labeled as mock/example.
