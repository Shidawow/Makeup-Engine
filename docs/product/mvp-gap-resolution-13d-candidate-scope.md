# MVP Gap Resolution 13D Candidate Scope

Phase 13D should be a focused demo-gap resolution sprint, not a production
roadmap execution phase.

## Candidate 13D Scope

| Candidate | Owner role | Acceptance signal |
| --- | --- | --- |
| User App first-run clarity polish | UX / product | First screen makes the next user action obvious without administrator terms |
| Trial template content consistency polish | Makeup content | Three MVP trial templates use consistent structure, tools, difficulty, and completion cues |
| Step guidance trust wording polish | UX / trust privacy | Steps include completion and correction cues without claiming automatic recognition |
| Mobile demo touch target / spacing polish | UX | Mobile demo controls remain readable, tappable, and low-density |
| Operator workflow explanation tightening | Operator workflow | Photo-to-template remains candidate-only, semi-automatic, and human-review-required |

## 13E Or Later

13E can take follow-up polish after Sprint 1, especially items that require more
founder choice or more internal evidence. Trust copy depth can move into 13D
only if the founder explicitly chooses that scope.

## Deferred Production Gaps

Defer:

- backend / database / accounts
- analytics and real user feedback collection
- production registry write
- payment
- App Store / TestFlight
- public user growth
- fully automatic high-quality makeup extraction

These gaps are documented but are not current must-do work.

## Stop Conditions

Pause Phase 13D planning if the scope starts to include:

- registry write, registry mutation, publish, production writer, or User App
  Shell package replacement
- backend, analytics, real user feedback collection, camera, AR, OpenAI API,
  external AI API, or model training
- personal data, real user photos, base64 images, local photo paths, or
  biometric data
- claims that arbitrary photos can be fully automatically converted into
  high-quality makeup templates
