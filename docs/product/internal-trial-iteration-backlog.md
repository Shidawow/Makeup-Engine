# Internal Trial Iteration Backlog

Phase 9C backlog converts anonymous/mock issue summaries into local action items. It is a planning aid, not a backend issue tracker and not a real participant record system.

## Backlog Item Fields

Each item records:

- issue category
- severity
- confidence
- actionability
- owner area
- recommended fix type
- target iteration
- acceptance criteria
- blocked reason, when privacy or scope must stop the next trial

## Owner Areas

- `template_content`: template copy, steps, regions, tools, products, difficulty, trial suitability.
- `user_app_shell`: home, navigation, mobile layout, touch controls, state clarity, admin/user separation.
- `trial_pack`: trial task order, operator script, observation template, feedback summary.
- `privacy_boundary`: no photos, no identity, no upload, no backend, no AI analysis, no training.
- `discovery_recommendation`: recommendation reason and template discovery clarity.
- `session_preference`: local-only progress and non-sensitive preference clarity.
- `observe_more`: insufficient or unclear anonymous signals.

## Status

- `backlog_ready`: no immediate fix items.
- `backlog_ready_with_warnings`: one or more actionable or observe-more items exist.
- `backlog_blocked`: privacy, sensitive data, backend, upload, AI analysis, training, or scope boundary risk exists.

## Boundary

Backlog items are anonymous/example-level planning records only. They must not contain real participant identities, contact details, photos, health information, sensitive identity information, biometrics, backend ids, analytics ids, training labels, or raw user feedback records.
