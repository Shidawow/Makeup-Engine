# Source Image Artifact Binding

Phase 6H-4 adds an explicit browser handoff for source image artifacts.

`source-image-manifest.json` can reference normalized PNG, JSON RGBA, and raw RGBA artifacts generated by the CLI import pipeline. Those references are package-relative paths. They are not browser-readable files.

The Studio must follow this flow:

```text
SourceImagePackage manifest
-> SourceImageEntry
-> operator explicitly binds artifact files
-> SourceImageArtifactBinding
-> BrowserArtifactResource
-> TemplateAnalysisSeed readiness update
-> Vision Analysis
```

Forbidden flow:

```text
SourceImagePackage
-> training dataset
```

## Operator Flow

1. Import or paste `source-image-manifest.json` in Template Studio.
2. Select a ready source image entry.
3. In Artifact Binding, choose the corresponding local artifact file.
4. Bind normalized PNG first when available.
5. Create `TemplateAnalysisSeed`.
6. If the binding is validated, the seed can become `ready_for_vision_analysis`.
7. Run Vision Analysis from the seed.

## Supported Artifacts

- `normalized-png`: creates a browser object URL from an explicitly selected `File`. This can be used as image preview and Vision Analysis input.
- `json-rgba`: parses JSON RGBA and validates width, height, and channels. A preview data URL is generated only when the browser canvas API is available.
- `raw-rgba`: currently a summary-only boundary. It is not faked as a browser preview or analysis image.

## Storage Rules

- Do not store local absolute paths.
- Do not store large image bytes in session storage.
- Do not assume object URLs survive a page refresh.
- Do not treat manifest relative paths as browser-readable.
- Do not allow `SourceImagePackage` to bypass correction or review queue.
